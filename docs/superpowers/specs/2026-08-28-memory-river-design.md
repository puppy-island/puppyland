# 第二阶段“记忆之河”前端优化设计

## 1. 目标与范围

把当前第二阶段“普通的一天”房间点击交互改造成一段连续的记忆旅程：小狗以透明、未成形的灵魂状态出现，向前奔跑并渡过一条河；用户逐条输入或录音，提交的真实记忆沿途出现，小狗随记忆累积逐步变得完整；最后小狗跑过彩虹桥，进入现有第三阶段流程。

本次范围只覆盖第二阶段及其进入第三阶段的过渡，不重做开场、第一阶段和 Companion 叙事规则。`swimming.png` 作为第二阶段全屏主背景，保留当前项目纯前端、零依赖、Mock ASR、Guest Session 本地持久化的约束。

## 2. 交互原则

1. 一次只采集一条记忆，用户提交后停住，不自动跳到下一条。
2. 每条记忆提交后先完成一小段“记忆出现 + 小狗前进/变完整”的演绎，底部显示“继续前进”，用户点击后才进入下一条。
3. 支持两种输入入口：文字输入和按住录音。录音完成后必须先显示可编辑的识别文字，再允许提交。
4. 记忆内容由用户输入驱动，不使用固定示例文案替代用户内容。提示语只负责帮助用户回忆，不写入 Memory。
5. 所有动画都服务于“被记住后更完整”的因果关系：记忆出现前小狗透明且模糊，记忆出现后增加不透明度、细节和色彩。

## 3. 记忆段落与状态机

第二阶段包含五个顺序段落，提示语可按产品文案调整，但顺序和数量保持稳定：

| step | 引导主题 | 记忆优先级 | 视觉变化 |
| --- | --- | ---: | --- |
| 0 | 第一次见面 | 2 | 小狗从远处出现，透明度略升 |
| 1 | 第一次把 TA 带回家 | 2 | 小狗靠近河岸，轮廓开始成形 |
| 2 | 主人给 TA 喂饭/照料 | 1 | 水面出现暖色记忆光点，小狗身体变实 |
| 3 | 只有你们知道的小习惯 | 2 | 小狗进入奔跑姿态，细节明显增加 |
| 4 | 一段特别幸福的时光 | 3 | 小狗达到完整状态，彩虹桥显现 |

建议新增或重构为以下状态字段，沿用现有 `S` 对象并保持向后兼容：

```text
S.story.scene = 'memory-river'
S.story.riverStep = 0..4
S.story.riverSubmitted = false
S.story.riverAwaitingContinue = false
S.story.riverComplete = false
S.story.riverMemories = [{ step, memoryId, text, createdAt }]
S.story.dogCompleteness = 0..1
```

页面加载时，如果 Guest Session 已处于第二阶段，必须恢复到最后一个未完成段落；如果 `riverComplete` 为真，则继续显示彩虹桥过渡或直接恢复第三阶段，不重复要求用户输入已完成的记忆。

## 4. 页面结构与视觉层

第二阶段沿用现有 `.scene` / `.world` / `.dock` 骨架，替换 `room2` 内部物件为分层旅程结构：

1. **背景层**：`swimming.png` 全屏覆盖，使用 `background-size: cover`，通过深浅渐变遮罩保证底部输入区和文字可读；不拉伸图片比例。
2. **环境层**：河面流动、水纹、远处光带、记忆光点和已走过的脚印。动画只使用 CSS transform/opacity，避免引入 Canvas 或 WebGL。
3. **角色层**：复用现有 `pet-*.webp` 姿态资源，新增 `river-dog` 定位容器。初始使用 `opacity`、`filter: blur()` 和低饱和度；每段提交后由 CSS 变量 `--dog-completeness` 驱动恢复清晰度。
4. **记忆层**：每条已提交记忆生成一个 DOM 卡片或短句气泡，显示用户原文（超长文本截断并支持展开），并在对应位置生成发光记忆点。敏感 Memory 仍遵守现有 `groundingAllowed: false` 规则，不进入角色画像或后续叙事 grounding。
5. **交互层**：底部 dock 显示当前提示、文字输入、录音入口；提交后切换为记忆回放状态，只保留“继续前进”按钮。
6. **过渡层**：第五条记忆完成后出现彩虹桥，角色切换 `run` 姿态并沿桥移动；动画结束调用现有 `goto('s3')`，保留第三阶段选择重要记忆的流程。

## 5. 单条记忆交互流程

每个 `riverStep` 使用相同的可复用交互协议：

1. 显示该段引导文案和“写下来 / 按住录音”输入区。
2. 用户输入文字，或按住录音；松开后调用现有 `mockASR()`，把识别结果放回可编辑文本框。
3. 用户点击“记下这段”提交。空文本不提交，输入框保留焦点并给出轻提示。
4. 提交成功后调用 `addMemory('s2', text, priority)`，创建对应 paw mark，并将 `{step, memoryId, text}` 写入 `riverMemories`。
5. 播放该段演绎：记忆卡片淡入、光点亮起、小狗沿河前进、`dogCompleteness` 增加；期间禁用输入控件，避免重复提交。
6. 演绎结束后显示“继续前进”。点击后递增 `riverStep`，清理上一段临时控件，显示下一段引导。
7. 第五段点击“继续前进”后播放彩虹桥过渡，设置 `riverComplete = true` 并进入 `s3`。

## 6. 数据流与持久化

用户原文是唯一事实来源。现有 `addMemory()` 继续负责敏感检测、画像抽取和 `detail` 更新；第二阶段只新增河流专用索引，不复制或改写 `rawText`。视觉层从 `S.story.riverMemories` 和 `S.pawMarks` 渲染，避免把 DOM 作为状态源。

每次提交、点击继续、完成彩虹桥过渡后调用 `save()`。如果 `localStorage` 不可用，页面仍可继续当前会话，但刷新后不保证恢复；不弹出阻断式错误。

## 7. 异常与边界处理

- 文字为空：不推进，保留输入内容和焦点。
- 录音取消或未识别：关闭录音浮层，提示“没有听清，可以再说一次或直接写下来”。
- 识别结果过长：允许编辑，提交后视觉卡片只展示摘要，完整文本保存在 Memory。
- 连续点击提交/继续：按钮在演绎期间锁定，状态机以 `riverSubmitted` 和 `riverAwaitingContinue` 防重入。
- 用户刷新或返回第二阶段：按已持久化的 `riverStep` 和 `riverMemories` 恢复，不重复创建 Memory。
- `prefers-reduced-motion: reduce`：跳过奔跑、水纹和彩虹桥位移动画，但保留状态变化、记忆卡片和“继续前进”按钮。
- 小屏设备：输入区使用安全区 inset；卡片最大宽度不超过视口 84%，背景主体不被底部 dock 遮挡。

## 8. 验收标准

### 功能

- 第二阶段首屏显示 `swimming.png` 全屏背景和透明小狗。
- 五段记忆必须逐条收集；每条都支持文字提交和录音转可编辑文本。
- 每次提交后必须先完成演绎，再由用户点击“继续前进”；不能自动跳段。
- 刷新页面后能恢复当前段落、已提交记忆和小狗完整度。
- 五段完成后能看到彩虹桥过渡并进入现有第三阶段。
- 敏感文本不会进入画像和 Companion grounding。

### 视觉

- 初始小狗明显透明/模糊，最终状态清晰、完整、可辨识。
- 每条记忆在河面有可见的光点/卡片反馈，且不会遮挡输入区。
- 背景在桌面窄窗和手机竖屏下均保持覆盖，不出现横向滚动。
- 现有纸张色调、柔和阴影和暖色文字体系仍与第一阶段、第三阶段一致。

### 可访问性与回归

- 输入、录音、继续按钮可通过键盘操作并有 `aria-label`。
- 录音状态、提交成功和当前段落对屏幕阅读器可感知。
- 开场、第一阶段、第三阶段、Weave、Companion 和键盘快捷键不受影响。

## 9. 明确不做的事情

- 不引入第三方 UI 框架、Canvas、WebGL 或视频资源。
- 不在本次改造中实现真实 ASR、真实 AI 记忆解释或云端上传。
- 不重做第三阶段的记忆选择和 Companion 叙事模板，只调整第二阶段出口。
